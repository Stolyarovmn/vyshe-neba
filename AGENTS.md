# Agent rules — «Выше неба»

Для **каждого** запроса по игре сначала прочитать и применять:

1. `art/docs/ASSET_PRODUCTION_PIPELINE.md` — существующая производственная цепочка, approval, CI.
2. `art/docs/PRODUCTION_CONTRACT_V2.md` — обязательные preflight, engineering/era/projection/runtime gates; совместимое расширение.
3. `art/docs/RUNTIME_BRANCH_CONTRACT.md` — обязательное разделение production/history и чистой runtime/build ветки, правила двухступенчатого promotion и rollback. **Для branch/storage/promotion semantics этот документ имеет приоритет над более старым текстом pipeline/tracker.**
4. `art/docs/ASSET_GENERATION_RUNBOOK.md` — исполнимый порядок каждого production imagegen: preflight → deterministic request → immutable raw archive → source gate → processing/approval.
5. `art/docs/ASSET_TASK_TRACKER.md`, `art/docs/EXECUTION_TIMEOUT_POLICY.md` — resume и лимиты.
6. `art/style_bible.txt`, `art/docs/ERA_DESIGN_MATRIX.md`, `art/docs/ERA_REFERENCE_CONTRACT.md`, `art/references/eras/README.md`, `art/placeables/PRODUCTION_MANIFEST.md`, `art/placeables/PIPELINE_CONFIG.json`, `art/placeables/BASE_ISLAND_LAYOUT.json` по типу задачи. `ERA_DESIGN_MATRIX.md` — канонический visual/engineering language E0–E5; `ERA_REFERENCE_CONTRACT.md` — единственный допустимый формат era visual evidence; manifest остаётся источником gameplay role, parts, footprint и lineage конкретного объекта. Если для эпохи есть approved reference set под `art/references/eras/`, он обязателен как visual evidence.
7. `https://github.com/studioigor/ref2game/blob/main/codex/SKILL.md` — обязательный workflow ref2game.
8. Для новых/изменяемых assets: `art/docs/ASSET_BRIEF_TEMPLATE.md` и соответствующий `art/briefs/*` preflight receipt, если он существует.

**Проверить branch и SHA до действий.** `game-production` — production/history ветка с docs/scripts, approved production art, provenance и QA, но не полный runtime. `main` — чистая runtime/build ветка и текущий default branch: актуальный рендер сверять с `main:game/src/render/manifest.js` на выбранном SHA; runtime-art хранится только по каноническим `game/assets/...` путям. Не предполагать `game-build`, `clean-src` как canonical build branch или legacy `outputs/rocket` без проверки. Не подменять отсутствующие файлы выдуманными.

Для production imagegen, когда существует receipt, сначала запускать `tools/art_pipeline/validate_generation_preflight.py`, затем собирать фактический generation request через `tools/art_pipeline/build_generation_request.py`. Ручное перефразирование `art/style_bible.txt` вместо deterministic append запрещено. PASS этого preflight означает только разрешение на указанную стадию generation; он не открывает scene/runtime/promotion gates.

**Era gate обязателен до imagegen.** Для выбранной эпохи brief/prompt должен явно применять профиль из `ERA_DESIGN_MATRIX.md`: manufacturing/materials, drive, interface, lighting/signals, infrastructure, autonomy/service и silhouette. Для `E(n)→E(n+1)` фиксируются preserved/replaced/added/why/player signal; соседние эпохи не могут отличаться только recolor/glow. E4 использует robotics/autonomy и, для подходящей крупной архитектуры, выраженный glass/curtain-wall language. E5 использует sterile integrated design, spatial/holographic interfaces, contactless/levitating mobility и functional light lines только там, где это причинно оправдано; AI рисует физические emitters/lift hardware, code управляет active holograms, glow, fields и motion.

**Era reference sheets — только атомарный визуально-инженерный словарь.** Для каждой эпохи canonical set состоит ровно из четырёх ролей: `materials-construction`, `mechanics-infrastructure`, `controls-displays`, `lighting-signals`. Запрещены whole-object/application boards, целые здания, ангары, башни, машины, радары, краны, стартовые комплексы, staged base/room scenes и любые композиции, которые можно буквально скопировать как gameplay asset. Архитектурный/silhouette язык показывается через фрагменты конструкции, соединения, профили, фасадные/панельные узлы и service details. Один imagegen call = одна роль одной эпохи; четыре роли не объединять в broad era board.

**Approved era references обязательны, когда существуют.** Перед generation/review прочитать `art/references/eras/<era>/reference-set.json`, проверить SHA-256/Drive provenance и использовать все применимые атомарные листы по их ролям вместе с era matrix и asset-specific brief. Встроенный AI-текст/pseudo-text на reference sheets не является правилом. Переносится только язык эпохи — материалы, конструкция, механика, интерфейсы, свет и инфраструктура — а не идентичность или компоновка показанного объекта.

**Promotion разделён на две границы.** Candidate с exact-SHA visual approval сначала попадает только в `game-production` (`art/gen` + provenance/QA) через production PR. Затем отдельный runtime-publish берёт exact approved bytes и создаёт отдельный PR в `main`, заменяя уже существующий канонический `game/assets/...` файл **на том же пути**. В `main` запрещены production history/candidates/raw/QA и backup-копии старых картинок (`*_old`, `backup`, parallel mirrors). Rollback runtime — через Git history/revert. Если runtime target/consumer не подтверждён или target ещё не существует, runtime publication `BLOCKED` до отдельного integration PR.

Пока default branch = `main`, production-only workflows не копируются в `main` ради `workflow_dispatch`. Канонический trigger — ephemeral command branch от точного текущего `game-production` SHA: `asset-promote/**` меняет только `.asset-command/promote.json`, `asset-publish-runtime/**` — только `.asset-command/publish-runtime.json`. Workflow обязан проверить exact `production_base_sha`, отсутствие любых иных diff и сбросить command-only commit перед staging production/runtime changes.

После tracker migration канонические финальные шаги: `visual_review → promote → publish_runtime → game_tests`. `promote` не означает, что арт уже находится в игре; `publish_runtime` не считается завершённым только из-за создания PR — нужно подтверждение merge/resulting runtime SHA.

**Нельзя:** обходить SHA-bound approval, менять originals, считать candidate production, угадывать pivots/проекцию (47° не подтверждено), генерировать E0–E5 одной доской, использовать whole-object/application era references, анимировать механизм целым PNG, добавлять eventless FX, сводить эпохальную эволюцию к recolor/cyan/glow, делать direct push в `main`, смешивать production files с runtime PR или заявлять о непроверенном CI. Новые правила и исправления — через ветку/PR с QA и rollback. При отсутствии данных — `UNKNOWN/BLOCKED` с конкретной причиной.

Текст для пользовательских настроек ChatGPT Project: `art/docs/GAMES_PROJECT_INSTRUCTIONS.md`. Настройки проекта меняет сам пользователь, этот файл их не применяет автоматически.
