## Решение владельца (2026-11-07)

Владелец принял перечисленные отклонения (кромка плиты 0,92–0,95, глубина плиты, размер двери) и дважды ответил «Принять отклонения»; второй ответ относится к вопросу о хромакее и понят как принятие **ключа с допуском ±8 по каналам** вместо перегенерации. Это исключение надо записать в preflight-квитанцию (`generation_gate.alpha_strategy = opaque_chroma_key`, допуск) при встраивании. Визуальное утверждение (exact-SHA) это решение не заменяет.

## Блокер перед обработкой: фон не точный ключ

У всех четырёх исходников фон около `(247, 8, 249)` с шумом ±8 по каналам (точных пикселей `#FF00FF` на периметре нет). По `SOURCE_ALPHA_TRANSPORT.md` исходник с `opaque_chroma_key` обязан иметь точный объявленный ключ; для B03 E0 режим из-за разных оттенков фона уже возвращали на `native_transparent`. Обработка (`source_prepare` → Pixel Snapper → normalize → Aseprite) не запускалась. Варианты: (1) перегенерировать с настоящей прозрачностью; (2) зафиксировать исключение «ключ с допуском ±8» в preflight-квитанции и считать это решение владельца. Для просмотра сделан `island_compare_TEST_ONLY.png`: слева старые спрайты, справа новые на утверждённом острове (допусковой ключ, уменьшение до ширины старого спрайта, без Pixel Snapper; координаты размещения тестовые, не утверждены).

Измерения: `vn-gen/tools/measure_slab.py` (маска маджента-фона; кромки плиты на строках у её краёв) и визуальная оценка высот. Это грубая проверка источника, не замена гейту.
