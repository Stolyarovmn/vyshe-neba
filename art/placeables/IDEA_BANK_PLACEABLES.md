# Банк идей размещаемых объектов

Источник истины о ролях и эффектах — main:game/src/data/buildings.js и main:game/docs/DESIGN.md §4.4; этот файл — банк идей и правила rig/состояний.

Статус «взято» относится только к указанному эффекту или решению, а не ко всей исходной механике. Новые постройки и эпохи не заказываются автоматически по этому банку.

## Эпохи

| Эпоха | Год | Инженерный язык |
| --- | --- | --- |
| E0 | 1978 | Ручная сборка, сварная сталь, дерево, стрелочные приборы |
| E1 | 1986 | Гидравлика, окрашенные шкафы, ранняя электроника |
| E2 | 1998 | CRT, стойки аппаратуры, сервоприводы |
| E3 | 2015 | Модульное оборудование, композиты, закрытые приводы |
| E4 | 2035 | Роботизированные ячейки и автономные манипуляторы |
| E5 | 2060 | Лёгкие интегрированные системы с читаемой физической функцией |

Родословная сохраняет узнаваемость машины. Переход эпох меняет минимум три оси и сохраняет два признака семейства по [матрице эпох](../docs/ERA_DESIGN_MATRIX.md); перекраска и свечение не заменяют инженерную эволюцию.

## Runtime contract

- Логическая сцена — 960×600; размеры и якоря берутся из закреплённого `main:game/src/render/manifest.js`, а не из старых целевых размеров банка.
- Наземный якорь — низ по центру, если манифест не задаёт иное. Pivot измеряется на утверждённом спрайте; до измерения — `null` с причиной.
- Независимо движущиеся части полные, включая скрытые участки, с общей регистрацией и масштабом. Свет, дым, тени и частицы создаёт код.
- При упаковке атласа эпох: верхний ряд E0/E1/E2, нижний E3/E4/E5. Для отдельной детали — отдельный атлас; отсутствующая деталь даёт прозрачную ячейку прежнего размера.
- Сначала утверждается E0, затем части и варианты следующей эпохи по E0 и предыдущему утверждённому варианту; после нормализации измеряются pivot и проверяется сборка в сцене.

## Animation state contract

Машина мира: `OFF → IDLE → NOTICE → WORK → FINISH → COOLDOWN → IDLE`. `WORK` вызывается реальным событием игры; неподвижная база не покачивается целиком. Наблюдаемые состояния `PRESS / ON / BLOCKED / DENIED`, длительности и объём клипов по двум камерам заданы в [ASSET_STATE_SPEC](../docs/ASSET_STATE_SPEC.md), включая решение §6. Эта схема не требует рисовать клип каждому объекту.

## Родословные E0–E5

Это словарь для будущего арта, не очередь производства.

## Prompt recipe

Запрос описывает один объект или один ряд одной камеры: имя/ключ, роль из кода, эпоху и стадию родословной, камеру, реальный масштаб, опорную или отдельную физическую часть и её соединения. Полный силуэт без обрезки; без текста, логотипов, запечённых теней и FX; свет сверху-слева; исходный фон `#FF00FF`, прозрачность после обработки. Камера и палитра — по [ART_DIRECTION_HD_PIXEL](../docs/ART_DIRECTION_HD_PIXEL.md), состав запроса — по [SPRITE_REQUEST](../docs/templates/SPRITE_REQUEST.md). В автоматическом запросе `build_generation_request.py` порядок: заголовок области → канонический промпт → `art/style_bible.txt` дословно один раз.

## QA gates

Проверяются функция и силуэт в игровом размере, целостность частей, измеренные pivot и совпадение сборки в покое с опорным артом. Для нужного по §6 клипа проверяются кадры, переходы без скачков и причинное игровое событие. Смена эпохи сохраняет привязки. Готово = скриншот из игры принят владельцем; отдельный PNG или автоматический отчёт приёмку не заменяет.

## Renderer requirement

Покупаемая инфраструктура — самостоятельные слои: оболочка сцены → задние объекты → ракета/машины → передние объекты → FX → UI. Покупки не запекаются навсегда в фон. Движение делает код из физических частей; реализация и публикация — по [контракту публикации](../docs/RUNTIME_BRANCH_CONTRACT.md).
