# Стиль запроса на генерацию объектов E0 (рабочая схема)

> **Статус 2026-11-10.** Камера 73,44° и правило «начинка вместо крыши» действуют только для спрайтов сцены полёта (`base/`). Для хаба владелец выбрал изометрию 40°; способ генерации и обработки всех спрайтов E0 описан в `ART_DIRECTION_HD_PIXEL.md`, он имеет приоритет над этим документом.


Назначение: единый каркас prompt для imagegen-запросов по объектам базы E0, чтобы сохранить проработанность (плотные материалы, читаемая конструкция) и не нарушать правила конвейера: камеру, единообразие, симметрию, пропорции. Каркас **не заменяет** `tools/art_pipeline/build_generation_request.py` и `production_guard.py`: когда для типа генерации есть детерминированный builder, он собирает итоговый запрос, а этот документ описывает содержание блока `SUBJECT`.

## Порядок блоков запроса

1. `art/style_bible.txt` — **дословно**, один раз (сам builder вставляет его в конец).
2. `ONE ASSET` — один объект, одна эпоха E0, один кадр. Целые сцены, соседи и декорации запрещены.
3. `SUBJECT` — что это и **зачем** оно в игре одной фразой из паспорта, сверенного с `main:game/src/data/buildings.js`: например «центр управления: телеметрия и прогноз траектории». `IDEA_BANK_PLACEABLES.md` содержит идеи и родословные, а не реализованные эффекты.
4. `PARTS` — закрытый список физических частей. Каждая часть: назначение, размер относительно двери 0,9 × 2,0 м, как она крепится (шов, болт, хомут). Всё, чего нет в списке, запрещено.
5. `ERA E0` — материалы и конструкция из `ERA_DESIGN_MATRIX.md` E0: сварной и болтовой профиль, крашеная листовая сталь olive/серо-зелёный/грязно-бежевый, ржавчина по кромкам и сварным швам, бетонный цоколь, крупная incandescent-лампа в защитной сетке, стрелочные приборы. Запрещены чистый пластик, плоские экраны, тонкие LED-ленты, неоновая подсветка, декоративный cyan.
6. `EVIDENCE` — приложенные листы `art/references/eras/e0_1978/` по ролям (какой лист для чего: стыки и сварка — `materials-02`, двери и кровля — `materials-03`, приводы — `mechanics-01/02`, кабели — `mechanics-03`, лампы — `lighting-01/02`) с пометкой: переносится язык эпохи, а не буквальные объекты; встроенный текст листов не правило.
7. `CAMERA` — камера `island_top_3_4`: приложены утверждённый остров и схема массы. Контрольные значения: 73,44° над горизонтом, сжатие земли 0,9585, видимая высота стены умножается на cos 73,44° ≈ 0,285 (фронтальная стена низкая, крыша доминирует). **Дальняя кромка основания на 1–6 % уже ближней** (трапеция, широкое основание ближе к зрителю; обратная трапеция — немедленный отказ). Свет только сверху-слева, запечённой тени нет.
8. `SCHEMA` — приложенная схема массы задаёт силуэт, пропорции и проекцию: генератор раскрашивает и детализирует её, **не меняя контур, число и положение частей**. Схема не источник стиля и не попадает в кадр.
9. `ALPHA` — фон однотонный `#FF00FF` без градиента и теней (chroma-key по `SOURCE_ALPHA_TRANSPORT.md`), объект целиком, поля со всех сторон.
10. `EXCLUDE` — текст, цифры, логотипы, UI, сцена, земля вокруг (кроме собственной плиты/цоколя объекта), лучи, свечение, дым, пар, запечённая тень, размытие движения, любые части вне списка PARTS.

## Композиция под камерой 73,44°: интересна начинка, а не крыша (правило владельца, 2026-11-07)

Фронтальная стена под этой камерой видна на 0,285 своей высоты, поэтому «здание с крышей» превращается в плоскую крышу и пустой серый квадрат (так выглядела попытка BI_CONTROL attempt02: крыша ≈ 85 % спрайта). Менять угол острова ради этого нельзя: он калибровочный для всех утверждённых объектов (`art/gen/environment/start_island_hd.projection.json`). Поэтому меняется композиция:

1. **Закрытый объём узкий.** Верхняя плоскость крыши ≤ 40 % площади основания спрайта (проверяется по схеме: `roof_share_of_slab_schema` в `*.json` рядом со схемой).
2. **Ради чего объект куплен — на горизонтальных плоскостях**: на крыше-плите (антенны, вытяжки, люки, труба), на дворе перед входом (траншеи с плитами, рельсовый путь, седла с изделием, шкафы ввода, кран-укосина). Эти плоскости видны почти полностью.
3. **Плита основания не шире содержимого.** Пустой бетон по краям запрещён: габарит плиты — содержимое плюс проход 0,3–0,5 м.
4. **Крыша не равна декору.** На ней только узлы, у которых записан ответ «зачем» (приём телеметрии, вытяжка, люк, труба); гофр и заклёпки — материал, а не содержимое.

Схемы: `art/briefs/assets/E0_{control,recovery,factory}_schema_v2.png/.json`, `E0_logistics_schema_v3.png/.json`, код `tools/art_pipeline/e0_massing_objects.py`.

### Что делать с камерой в самом запросе (проверено 2026-11-07, см. `E0_REWORK_TRACKER_20261107.md`)

Слова «73°, почти сверху» генератор игнорирует и рисует изометрию около 45–50° (стены втрое выше нормы). Поэтому в блок `CAMERA` и в корректирующую вторую попытку записываются **числа в пикселях**: масштаб (`ширина плиты в px / ширина в м`), ожидаемая высота вертикали `H·0,285·масштаб` и фактическая измеренная высота в предыдущей попытке. Вторая попытка с такими числами у четырёх объектов давала верную вертикаль. Первая попытка считается разведкой камеры; её оригинал архивируется как отказ.

Схема массы должна быть **смыслово верной**: у грузового терминала v2 ставила ящики за стойки портала, генератор послушно нарисовал груз, до которого таль не достаёт. Перед отправкой схема проходит чек «каждая рабочая связь достижима» (груз под балкой, трос от барабана к стреле, кабель от шкафа к стене).

## Приёмка источника (source gate) — строго, до обработки

Измеряется на нетронутом PNG и записывается в `*.pipeline.json`/бриф:

| Проверка | Порог | Как |
| --- | --- | --- |
| Дальняя кромка основания / ближняя | 0,94–0,99 | по четырём углам основания |
| Глубина основания / средняя ширина | совпадает с пропорцией схемы ± 3 % (для прямоугольника `D·0,9585 / W`) | те же углы |
| Видимая высота фронтальной стены | не выше `H·0,285 ± 10 %` | по краю карниза и цоколя |
| Симметрия | зеркальные узлы (опоры, створки, фланцы) совпадают по размеру ± 5 % и стоят на одной линии перспективы | по меткам |
| Размер | двери/люки/лестницы соответствуют масштабу 0,9 × 2,0 м; нет гипертрофированных деталей (маховик, лампа, труба) | сравнение с дверью |
| Доля крыши | верхняя плоскость крыши ≤ 40 % площади основания; остальное — функциональное содержимое (см. раздел «Композиция») | площадь крыши / площадь плиты по маске |
| Осмысленность | у каждой видимой детали есть записанный ответ «зачем» | чек-лист в брифе |
| Палитра | нет вне E0 цветов (синий, cyan, фиолетовый, белый пластик) | визуально + выборка цветов |
| Запрещённое | нет запечённой тени/света, текста, лишних частей | визуально |

Любое нарушение → `source reject` с причиной, оригинал архивируется в Drive как есть, следующая попытка меняет **только** найденный дефект. Обработка (Pixel Snapper, normalize, Aseprite) начинается только после прохождения.

## Схемы массы

Схема массы строится кодом `tools/art_pipeline/e0_massing.py` из тех же размеров, что и бриф: основание, коробка здания, крыша, места дверей и вводов. Проекция: `sx = X·f(Y)`, `sy = Y·sin 73,44° − Z·cos 73,44°`, где `f` линейно уменьшается к дальнему краю до 0,955. Схема кладётся рядом с утверждённым островом, чтобы проверить масштаб; она остаётся `TEST_ONLY` и не определяет координаты на карте (это отдельный этап в Map Editor).
