# Спецификация рабочих состояний объекта

Назначение: описать, **что видит игрок** у каждого покупаемого или размещаемого объекта при нажатии, включении, блокировке и отказе. Документ дополняет `PRODUCTION_MANIFEST.md` §3 (машина состояний `OFF → IDLE → NOTICE → WORK → FINISH → COOLDOWN`): та машина описывает жизнь объекта в мире, эта спецификация — то, что игрок наблюдает и что обязано быть нарисовано или анимировано.

Не у всякого объекта есть все четыре состояния, но **у каждого покупаемого объекта должно быть не меньше двух**, одно из которых анимированное (иначе объект мёртв). Анимация всегда привязана к игровому событию; «дыхание», покачивание целого спрайта и вечные циклы запрещены (`MANIFEST` §3, `animation.json` каждого объекта).

## 1. Четыре состояния

| Код | Что это | Когда наступает | Что видит игрок | Рисует арт или код |
| --- | --- | --- | --- | --- |
| `PRESS` | нажатие | тап по объекту или по его органу управления, наведение курсора | физический отклик за ≤ 0,25 с: орган управления утапливается на 1–2 логических пикселя, рычаг стоит в промежуточном положении, лампа мигает один раз; выноска открывается у объекта | подвижные части — арт (отдельные кадры/части); лампа, звук и тень нажатия — код |
| `ON` | включение, работа | объект куплен и запитан; игровое событие запускает `WORK` (`safe_landing`, `launch_prepare`, `contract_complete` …) | заметное механическое действие: стрела поворачивается, барабан крутится, стрелка прибора идёт, лампа `ready` горит; после события возврат к `IDLE` | части и их кадры — арт; свет, свечение, дым, звук — код |
| `BLOCKED` | блокировка | условия покупки или работы не выполнены: нет эпохи, нет соседней постройки, нет питания | объект не движется и не светится; причина видна на самом объекте: заглушка на штуцере, стопор на рычаге, обесточенная лампа, брезент на механизме; в выноске — причина словами из `reasonFull` (эпоха, постройка, питание) | состояние покоя — арт (вариант без движения), надпись причины — код (UI) |
| `DENIED` | отказ | игрок нажимает на заблокированный объект или кнопку «купить» без денег/данных | короткая (≤ 0,4 с) реакция: механический упор «клацает» (смещение детали 1 пиксель и возврат), красная лампа мигает один раз, выноска дрожит (уже есть в `kit.button`); состояние объекта не меняется | смещение детали — арт-часть, дрожание и звук — код |

Соответствие с машиной мира: `BLOCKED` и ещё не построенный объект ≈ `OFF`; `PRESS` — часть `NOTICE`; `ON` = `WORK` + `FINISH`; `DENIED` не меняет состояние и не входит в машину.

## 2. Что должна содержать запись

Файл `states.json` рядом с `animation.json` объекта:

```json
{
  "asset": "B07 cargo_terminal",
  "era": "E0",
  "states": {
    "PRESS":   { "trigger": "tap", "parts": ["hand_chain"], "motion": "цепь тали смещается на 1 звено", "frames": 2, "fps": 12, "loop": false, "code_fx": ["click_sound"], "why": "…" },
    "ON":      { "trigger": "contract_complete", "parts": ["trolley", "hoist", "hook", "container"], "motion": "каретка идёт по балке, крюк опускается, контейнер уходит на платформу", "frames": 24, "fps": 12, "loop": false, "reduce_motion": "статичный кадр с контейнером на платформе", "why": "…" },
    "BLOCKED": { "trigger": "requirement_missing", "reasons": ["era", "building:logistics", "power"], "visible": "тележка стоит у упора, на цепи красная бирка", "art_variant": "idle_locked", "why": "…" },
    "DENIED":  { "trigger": "tap_while_blocked", "motion": "упор каретки дёргается на 1 px", "frames": 2, "fps": 12, "loop": false, "code_fx": ["red_lamp_blink", "shake"], "why": "…" }
  },
  "not_applicable": ["…с причиной"],
  "accessibility": "при «меньше движения» остаётся один конечный кадр каждого состояния"
}
```

Обязательные поля каждого состояния: `trigger` (событие игры или жест), `parts` (какие **физические части** движутся; целый спрайт не движется), `motion` (одной фразой), `frames`/`fps`/`loop`, `code_fx` (что делает код), `why` (зачем игроку это видеть — из игрового процесса, не из декоративных соображений). Неприменимое состояние записывается в `not_applicable` с причиной.

## 3. Правила для арта и анимации

1. Анимация складывается из **отдельных физических частей** (стрела, каретка, лампа, дверца), а не из деформации всего спрайта. Опорная часть (основание, плита, стойка) не движется и не вращается.
2. Каждая подвижная часть имеет измеренный pivot после обработки (`animation.json` → `pivot_policy`); пока pivot не измерен, он остаётся `null`.
3. Длительности: `PRESS` ≤ 0,25 с, `DENIED` ≤ 0,4 с, `ON` — по событию, не дольше 3 с без новой причины. Частота кадров 8–12, число кадров минимально достаточное: пиксельная анимация читается по ключевым позам.
4. Анимации в GIF/спрайт-листе делаются из частей, утверждённых как неподвижные кадры. Каждый кадр проходит те же проверки проекции, симметрии и размеров, что и статичный спрайт. Кадры строятся на **той же сетке и привязке**, что и опорный кадр; смещение деталей между кадрами — целое число пикселей сетки.
5. Свет, свечение, лучи, дым, пар, тень и звук принадлежат коду и в картинку не запекаются (`style_bible.txt`, «System separation»).
6. Блокировка показывается **физически и по причине**: стопор, заглушка, обесточенная лампа. Универсальный «серый фильтр» и замок поверх спрайта запрещены: замок в интерфейсе уже рисует UI.
7. `DENIED` не должен выглядеть как поломка: объект остаётся целым, реагирует один раз.
8. Каждое состояние должно отвечать на вопрос «зачем» (`why`), исходя из игрового процесса и эпохи: например, красная лампа `DENIED` у E0 — крупная incandescent-лампа (`ERA_DESIGN_MATRIX` E0), а не LED-полоска.

## 4. Минимальный набор по типам объектов E0

| Тип | Обязательные | Допустимо не делать |
| --- | --- | --- |
| Здание-потребитель (центр управления, цех) | `BLOCKED` (дверь заперта, лампа погашена), `ON` (дверь/вентиляция/лампа по событию) | `PRESS` и `DENIED` частично кодом (дрожание выноски) |
| Подъёмно-транспортное (тельфер, лебёдка, кран) | `PRESS` (ручной привод), `ON` (подъём/перенос), `BLOCKED` (стопор) | — |
| Ёмкости и магистрали (бак, топливо, охлаждение) | `ON` (вентиль, манометр), `BLOCKED` (заглушка) | `PRESS` |
| Приборы наблюдения (радар, метео, маяки) | `ON` (поворот головы/мачты — отдельные части), `BLOCKED` | `PRESS`, `DENIED` |
| Опоры и ворота | `ON` (створка/барьер), `BLOCKED` (запор) | остальное |

## 5. Проверка

Состояние принято, если: (1) для каждой подвижной части есть `pivot` или явная пометка `null` с причиной; (2) кадры совпадают с опорным по размеру холста и привязке; (3) в кадрах нет запечённого света и тени; (4) `why` каждого состояния выводится из `PRODUCTION_MANIFEST.md`/брифа/эпохи; (5) состояние не противоречит `reasonFull` (какие причины блокировки существуют в `game/src/ui/next-steps.js`).
