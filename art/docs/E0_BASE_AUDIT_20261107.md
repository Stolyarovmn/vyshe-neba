# Аудит готовых объектов базы E0 (на 2026-11-07)

Источник: ветка `art/e0-base-approved` (19 утверждённых пакетов `art/gen/placeables/base/*/e0_1978.runtime.png`), `game-production`, `main` (`game/src/render/manifest.js`). Оценка визуальная, по контактному листу в игровом размере; это **мнение автора аудита**, а не приёмка. Решение о замене принимает владелец продукта.

Критерии (из `ASSET_GENERATION_RUNBOOK.md`, `ERA_DESIGN_MATRIX.md` E0, `style_bible.txt`): камера `island_top_3_4` (прокси 73,44° над горизонтом, сжатие земли 0,9585, высота проецируется с `cos 73,44° ≈ 0,285`); дальняя кромка узка ближней на 1–6 %; нет запечённых теней и света; палитра E0 — olive / gray-green / steel / dirty beige, красный и жёлтый только функционально; каждая деталь отвечает «почему здесь» из игры.

## Что не хватает

1. У покупаемых зданий нет **записей рабочих состояний** (`states.json`, см. `ASSET_STATE_SPEC.md`): есть только `animation.json` с машиной мира.
2. Опорных схем проекции (massing-схем) для зданий, которые приходится переделывать: без них генератор не выдерживает отношение кромок 94–99 % (брифы BI-FACTORY, BI-GANTRY, B07 фиксируют отказ по этому критерию 5–9 раз).
3. Вспомогательных объектов у зданий мало, и это правильно: по `E0_SCENERY_RULES.md` каждое добавление требует маршрута или функции в игре.

## Порядок переделки

1. `control` (центр управления): простейшая геометрия — проверка процесса.
2. `logistics` (грузовой терминал): ручная таль, схема усилия сверена с руководством производителя в брифе B07.
3. `recovery` (спасательный комплекс): лебёдка, люлька, трос.
4. `factory` (цех): ворота, вытяжка, дымоход.

Остальное — только по просьбе владельца.
