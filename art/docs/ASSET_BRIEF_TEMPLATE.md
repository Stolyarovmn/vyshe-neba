# Паспорт объекта — одна страница

Создать `art/briefs/<объект>.md` для новой или изменяемой семьи. Паспорт описывает действующий объект; попытки, SHA исходников, замеры и отклонения записывать в `art/review/<ключ>/LOG.md`. Неизвестное обозначать `UNKNOWN` с причиной, не угадывать.

## Объект и эффект

- Объект / ключ в игре / эпоха: `<название / ключ из buildings.js / E0…E5>`.
- Источник роли: `main:game/src/data/buildings.js` и `main:game/docs/DESIGN.md` §4.4; закреплённый SHA: `<SHA>`. Банк идей не определяет действующие эффекты.
- Видимый результат покупки: `<одна фраза из действующей механики>`.

| Эффект из buildings.js и единица | Уровни 1 / 2 / 3 / 4 / 5 / 6 |
| --- | --- |
| `<ключ эффекта, % / шт. / мощность>` | `<числа из кода; доли для % перевести в проценты>` |

Числа — номинал; отметить влияние питания. Для энергоузла указать `power.supply` и `power.use`. Условия покупки и причина блокировки соответствуют коду и `reasonFull`, без новых механик.

## Части и состояния

- Физические части и соединения: `<опора; полные отдельные подвижные детали; назначение каждой>`; pivot `<измерен на точном арте / null с причиной>`.
- По [ASSET_STATE_SPEC](ASSET_STATE_SPEC.md) §6: `PRESS` — один показ существующего ON-клипа, если он есть; отдельный клип нажатия не рисовать. `ON` — `<конкретное событие и действие>`. `BLOCKED` — причина из `reasonFull` только на карточке «База»; `DENIED` — отклик карточки `kit.denyFx` ≤0,4 с, без изменения спрайта.
- Полёт `base/`: новые клипы не делать. База `iso/`: клип только для `gantry`, `rescue`, `factory`, `logistics`; у `deluge` вода кодом, остальным лампа/дым кодом. Целый PNG не покачивается; свет, тени, FX и звук — код.

## Текущие файлы и решения

- Проверить наличие в закреплённом main: `game/assets/eras/e0-1978/base/<ключ>.png`, `iso/<ключ>.png`, `icons/<ключ>.png`; отсутствующее явно отметить. Для `weather` проверить фактический `base/weather-complex.png` из манифеста.
- Отдельные части / ON: `<реальные пути, запись E0_BUILDING_CLIPS, число кадров и частота; либо «нет»>`. Кандидаты из другой ветки подписывать отдельно, не выдавать за main.
- Правила и решения владельца: HD-пиксель по острову; полёт сверху, база — изометрия 40°; `<подземные трассы, свободные проходы и другие решения именно этого объекта>`. Камера, палитра и родословная — по [направлению арта](ART_DIRECTION_HD_PIXEL.md) и [матрице эпох](ERA_DESIGN_MATRIX.md).
- Приёмка: **«скриншот из игры принят владельцем»**; читаемость и детали проверяются в игровом масштабе по `main:game/docs/QUALITY_BAR.md`, до новой генерации. PNG и численный замер отдельно не дают приёмку.

Журнал попыток: `art/review/<ключ>/LOG.md` — заменить эту строку одной относительной Markdown-ссылкой из паспорта. В журнале хранить исходные записи дословно, даты, SHA, Drive, проверки и отклонения; старые решения явно отмечать историческими.
