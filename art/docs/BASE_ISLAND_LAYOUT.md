# Стартовый остров и размещение развития базы

Этот документ является layout-контрактом земной базы `Выше неба` и используется вместе с `ASSET_PRODUCTION_PIPELINE.md`, `PRODUCTION_MANIFEST.md` и `ref2game`.

## 1. Стартовое состояние

Стартовая сцена Земли содержит только:

- конечный природный остров;
- стартовый стол и минимальную бетонную стартовую площадку, уже нарисованные в island asset;
- непрерывную воду вокруг острова;
- непрерывное небо/дальний горизонт.

В стартовый island asset **не запекаются** покупаемые здания, склады, ангары, радары, топливные объекты, краны, транспорт, люди, UI или погодные эффекты. Все покупки развития базы рисуются отдельными runtime placeable-ассетами поверх острова.

Канонический island runtime footprint:

```text
world left   = -448
world right  =  992
world top    =  335
world bottom = -267
launch pad   = (0, 0)
```

Остров конечный. При полёте вправо после `x ≈ 992` он полностью выходит из мира камеры; дальше остаются непрерывные вода + небо. Никакого fade прямоугольного background-layer нет.

## 2. Вода и погода

Вода не является частью island PNG. Runtime-код меняет её вместе с погодой:

| Состояние | Вода |
| --- | --- |
| Ясно | ярче, спокойные длинные блики, слабая рябь |
| Облачно | холоднее и темнее, больше ряби |
| Дождь | заметно темнее, частая короткая рябь |
| Гроза | глубокий сине-серый цвет, максимальная амплитуда/частота волн |

Тем самым природная береговая линия остаётся стабильной, а динамическая вода, свет и погода принадлежат коду.

## 3. Зоны развития

Покупки распределены по четырём функциональным зонам. Позиции детерминированы в `outputs/rocket/dist/island-layout.js` и используют существующие runtime slots инфраструктуры.

| Покупка | Runtime id | Слот | Зона | Логика размещения |
| --- | --- | --- | --- | --- |
| Стартовые маяки | `beacons` | `padL1` | Стартовое ядро | рядом с траекторией старта/посадки |
| Башня обслуживания | `gantry` | `padR1` | Стартовое ядро | непосредственно у стартового стола |
| Сервисная команда | `service` | `padL2` | Стартовое ядро | быстрый доступ к ракете |
| Охлаждение площадки | `deluge` | `padR2` | Стартовое ядро | максимально близко к стартовой площадке |
| Топливный комплекс | `fuel` | `apronL1` | Техническая зона | рядом со стартом, но вне огневой зоны |
| Спасательная станция | `rescue` | `apronR1` | Техническая зона | прямой выезд к площадке |
| Логистический терминал | `logistics` | `apronL2` | Техническая зона | возле сервисной дороги и складской площадки |
| Метеостанция | `weather` | `perL1` | Командный периметр | свободный сектор обзора, дальше от стартового стола |
| Радар слежения | `radar` | `perR1` | Командный периметр | чистый сектор обзора трассы |
| Центр управления | `control` | `perL2` | Командный периметр | отделён от стартовой и топливной зон |
| Наблюдательный комплекс | `observation` | `perR2` | Командный периметр | безопасная обзорная позиция |
| Система возврата | `recovery` | `remoteL1` | Дальний сектор | место под кран/транспорт и salvaged payload |
| Энергетический узел | `energy` | `remoteR1` | Дальний сектор | обслуживает соседние объекты, не мешая старту |
| Производственный цех | `factory` | `remoteL2` | Дальний сектор | наиболее крупная производственная площадка вдали от старта |

Все 14 runtime-покупок имеют уникальный слот. `BaseIslandLayout.validate()` проверяет наличие определения, совместимость zone и отсутствие повторно назначенного слота.

## 4. Полностью развитая база

QA обязан уметь собрать состояние `all purchases built` через `BaseIslandLayout.previewAll()` и проверить одновременно:

- все 14 покупок присутствуют;
- каждая находится в своём каноническом slot;
- ни один slot не используется дважды;
- стартовый стол остаётся читаемым;
- покупаемые объекты не являются частью island texture;
- остров естественно заканчивается и не повторяется за своими world bounds.

## 5. Portrait mobile

На touch-устройстве в портретной ориентации полёт использует вертикальный viewport без поворота всей игры на 90°:

- исходный 8:5 render сохраняет пропорции;
- viewport обрезается по горизонтали вокруг ракеты вместо растягивания;
- flight HUD переносится в DOM overlay по краям вертикального экрана;
- touch actions остаются доступными;
- landscape/desktop сохраняют прежний layout.
