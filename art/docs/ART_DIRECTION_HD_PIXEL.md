# Арт-направление «Выше неба»: HD-пиксель по эталону острова

Статус: действующий стандарт с 2026-11-09 (решение владельца: «остаёмся на HD-пикселе, который у нас был»; камера базы опущена до изометрии 2026-11-09). Этот документ отвечает на вопрос «как должна выглядеть каждая картинка в игре и как её получить». Он имеет приоритет над любыми более старыми описаниями камеры, масштаба и способа генерации игровых спрайтов (73° для зданий хаба, параметрические векторные исходники, Blender-спрайты). Он не отменяет `ERA_DESIGN_MATRIX.md` (чем эпохи отличаются по инженерии) и `ASSET_STATE_SPEC.md` (какие состояния обязаны быть у объекта).

## 1. Эталон

Эталон стиля — HD-остров: `main:game/assets/shared/island/start-island.png` (1916×821, байт-в-байт `art/gen/environment/start_island_hd.png`, SHA-256 `2b85ea5b…`). Всё остальное в кадре подтягивается к нему. Измерено скриптом `tools/hd_pixel/measure_style.py`:

| Свойство | Остров | Старые ракета/монета/кольцо (до 2026-11-09) |
| --- | --- | --- |
| Цветов | 252 | 2 900–4 700 |
| Полупрозрачный край | нет | 4–8 % пикселей |
| Средняя насыщенность / яркость | 0,47 / 0,54 | монета 0,87 / 0,78 |
| Самые тёмные 3 % (контур) | `#0a1518`, тёмно-бирюзовый | `#000000` |
| Свет | ровный, слева чуть ярче | блик справа, глянец |

Именно эта разница (тысячи цветов, глянец, чёрный контур, сглаженный край, другой свет) делала кадр похожим на склейку из разных игр.

## 2. Правила для любого спрайта

1. **Пиксель.** 1 px арта = 1 px острова для всего, что лежит на карте базы. Сцена полёта имеет одну свою плотность (корпус ракеты 120 px на холсте 146 px, `STACK_W = 24` ед. мира). Масштабирование делает код, не художник.
2. **Палитра.** Основа — 252 цвета острова (`hdpixel.island_palette`). На эпоху добавляется не больше 8 акцентов (для 1978: красный ракеты `#c74e45`, оранжевый сигнальный `#eb9d15`, латунь монет `#ef9453`, зелёный индикатор). Средняя насыщенность и яркость спрайта держатся у 0,45 и 0,55 ± 0,1.
3. **Край и контур.** Альфа только 0 или 255. Контур не чёрный: самый тёмный тон своего материала; у металла и теней `#0a1518`–`#2c4257`.
4. **Фактура и свет.** Пятна 2–4 px, без гладких градиентов и глянца. Металл — 3–5 тонов полосами. Один ключевой свет сверху-слева, тёплый на освещённых плоскостях, холодная сине-серая тень справа-снизу (формулировка из `style_bible.txt`). Теней на землю в спрайте нет — их рисует код.
5. **Крупнее правды.** Здание занимает свою полянку: след равен площади полянки, высота до 1,3 от реальной. Объект, который на экране меньше 40 px по большей стороне, не читается и не делается таким.
6. **Цельность.** Ракета — один непрерывный цилиндр из трёх частей одного диаметра; сопло ступени скрыто юбкой нижней, пока та не отделилась; купленная кабина видна с первого кадра. Кольцо ускорения — горизонтальный тор из двух половин (задняя под ракетой, передняя поверх).
7. **Цифры и текст.** Пиксельный шрифт с цифрой не уже 5 px и открытыми просветами у 0, 6, 8, 9. Текста на спрайтах нет никогда.

## 3. Три камеры и ничего кроме них

| Сцена | Камера | Источник геометрии | Файлы |
| --- | --- | --- | --- |
| Полёт (старт, взлёт, посадка) | остров строго сверху-3/4, proxy 73,44° — это сам HD-остров | `start-island.png` | `game/assets/shared/island/start-island.png`, постройки `eras/e0-1978/base/<key>.png` |
| База (хаб, управление) | ортографическая изометрия, 40° над горизонтом, взгляд на север, без поворота | рельеф острова поднят из `start-island.png` в Blender (`tools/hd_pixel/heightmap.py` + `iso_render.py`), форма, береговая линия и раскладка полянок те же, что в полёте | `game/assets/shared/island/base-iso.png` (1996×652), `base-iso.json`, постройки `eras/e0-1978/iso/<key>.png` |
| Иконки (магазин, карточки, модули, расходники) | фронт три четверти, крупный силуэт | нет | `eras/e0-1978/icons/<key>.png` 96×96, `icons/module_<id>.png`, `icons/item_<id>.png` |

Самолёты, шар, спутник — строгий бок (носом вправо), как в `style_bible.txt`. Любая четвёртая камера запрещена: один объект в двух камерах (карта и иконка) — норма, один объект под промежуточным углом — брак.

**Постройки на карте полёта (2026-11-11, кандидат до приёмки владельцем).** Перерисованы по просьбе владельца («Да, перерисовать») листами генератора с референсами «кроп острова — стиль» и «изометрический спрайт — сюжет»; запечены `tools/hd_pixel/bake_top.py` шириной изометрического спрайта той же постройки. Генератор нарисовал их круче изометрии, но не строго сверху (около 50–55°: видны фасады и крыши). Это сознательное исключение из правила выше: постройка выглядит одинаково на базе и в полёте, и при подъёме камеры (`render/flight.js`) изометрический спрайт без скачка переходит в спрайт карты. Если владелец отклонит, перегенерировать строго сверху по `templates/SPRITE_REQUEST.md` с референсом прежнего 73°-спрайта из истории `slice/e0-hd-pixel`.

Якоря базы: `base-iso.json` проецируется из якорей `BUILDING_ANCHORS` в `main:game/src/render/manifest.js` скриптом `write_layout.py`; руками правятся только поправки наложений (`OVERRIDES` в скрипте). Источник истины для координат — манифест на `main`; JSON производный.

## 4. Рецепт получения спрайта (как делались все спрайты E0 в ноябре 2026)

1. **Запрос.** Один чат генератора изображений (использовался ChatGPT, диалог «Create rocket sprite sheet»), в нём держится контекст стиля. К первому запросу прикладываются два референса: кроп HD-острова ×2 без сглаживания (стиль) и текущая картинка объекта (только сюжет и цвета, с пометкой «не копировать контур и глянец»). Фон строго `#FF00FF`, один объект или один ряд одинаковых ячеек, широкие поля, без текста, теней и эффектов. Камера называется словами из таблицы §3. Шаблон запроса: `templates/SPRITE_REQUEST.md`.
2. **Скачивание.** Оригинал сохраняется нетронутым (загрузка из Chrome оставляет `.crdownload`, но файл полный — копировать как PNG). Оригиналы кладутся на Google Drive по правилу `ASSET_PRODUCTION_PIPELINE.md` §5, если объект идёт в production history.
3. **Обработка** (`tools/hd_pixel/`): `hdpixel.key_out` (хромакей с снятием пурпурного ореола) → `pieces` (разрез листа на ячейки) → `resize_premul` (уменьшение с премультипликацией, чтобы край не темнел) → `accents` + `remap` (палитра острова плюс акценты) → альфа 0/255. Готовые скрипты: `bake_rocket.py`, `bake_ring.py`, `bake_icons.py`, `bake_items.py`, `bake_map.py`, `bake_seq.py` (общий: «путь:ширина» или «путь:ШxВ»), `bake_buildings.py` (пересборка старых 73°-зданий 1:1 с пикселем острова).
4. **Проверка.** `measure_style.py <png…>`: число цветов ≤ 300, полупрозрачных пикселей 0, насыщенность/яркость в допуске, контур не `#000000`, свет слева. Затем примерка в сцене (`composite.py` для базы) и скриншоты в игре.
5. **Встраивание.** Файл по пути из §3, размер в `manifest.js` (`E0_BUILDING_SIZES`, `ERA_SPRITE_SIZES`, `e0.size/footprint`), сборка `npm run build`, проверка в игре: база, ангар, лавка, запуск, полёт с отделением ступени.

Что такое «готово»: владелец видел скриншот из игры (не отдельный PNG) и принял. До этого объект — кандидат.

## 5. Что устарело и почему

| Было | Статус | Почему |
| --- | --- | --- |
| Генерация зданий хаба под 73,44° с «начинкой вместо крыши» (`E0_CLAUDE_PROMPT_STYLE.md`) | только для сцены полёта; для хаба заменено камерой 40° | владелец: «слишком высокий угол, для менеджмента на базе нужен пониже изометрический» |
| Параметрические векторные исходники (`E0_PARAMETRIC_VECTOR_SOURCE.md`) | не используются | геометрически верны, но суше и площе острова |
| Blender-модели 28 построек и Godot-просмотрщик (`trial3d/` в ветке `art/e0-rework2-20261109`) | архив | владелец остался на JS; спрайты из рендеров «суше старых» |
| Угол 47° | никогда не подтверждался | измерен proxy 73,44° |
| Spritesheet-пилоты Stardew-пикселя, плакат, low-poly (мудборд 2026-11-09) | отклонены | владелец выбрал HD-пиксель |
