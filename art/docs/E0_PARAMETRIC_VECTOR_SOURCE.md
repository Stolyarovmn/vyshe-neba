# Параметрический исходник жёсткого объекта E0

Для цеха BI-FACTORY применён самостоятельный кодовый SVG с прямым PNG-экспортом. Причина — imagegen менял жёсткие контуры и проекцию, несмотря на фиксированную схему. Это авторский векторный объект, а не обработка отвергнутых AI-картинок. Их оригиналы и причины отказа сохраняются отдельно.

Геометрия и материал строятся одними командами в SVG и PNG. Код содержит физические размеры, общую проекцию, крепёж и функциональные детали; передняя и задняя кромки вычисляются из тех же вершин. Фактическая камера острова остаётся UNKNOWN. Численный прокси 73,44° не заменяет обязательную сцену с утверждённым островом.

Изображение экспортируется непосредственно в логическую пиксельную сетку. Существующий adapter `prepared_grid_png` с `transport_scale:4` передаёт её через увеличение ближайшим соседом и Pixel Snapper `pixel_size:4`; это позволяет сохранить авторские границы. Обычный гладкий экспорт может быть деформирован Snapper и не принимается только потому, что исходный SVG математически верен. После обработки проверяется точное равенство обрезанных масок альфа и размер области, затем материал и читаемость в игровом размере. Для BI-FACTORY подтверждена область 242×170 и только вертикальный перенос на 32 пикселя.

PNG и SVG архивируются неизменными в Drive до обработки. В raw сохраняются исходники, код построения, библиотека проекции, их SHA и измеренные вершины. Старые версии не заменяются. Далее действуют прежние source gate, Pixel Snapper, normalize, Aseprite, SHA-bound визуальная приёмка, promote, отдельный runtime PR и проверки игры. Этот документ не отменяет ни одной границы публикации и не разрешает принимать автоматически другие объекты по одному совпадению контура.
