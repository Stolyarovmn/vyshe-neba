# W01 — Сервисный подъёмник (`service_lift`)

Нарезанный anchor-art для покупаемого объекта мастерской. Источник — утверждённый 3×2 atlas imagegen; стиль определяется `art/style_bible.txt`, роль и gameplay contract — `art/placeables/PRODUCTION_MANIFEST.md`.

## Runtime-нормализация

Исходный imagegen atlas имеет `1536×1024`, то есть шесть master-ячеек `512×512`. После alpha cleanup каждая эпоха нормализована в отдельный игровой PNG:

- canvas каждого спрайта: **`190×230 px` = `190×230 LP`**;
- видимое изображение вписано nearest-neighbor в envelope не более `178×218`;
- все эпохи используют общий placement baseline `x=95, y=224`;
- снизу оставлено 6 LP технического запаса;
- формат: indexed PNG8, максимум 32 цвета, без dithering;
- исходные пропорции сохранены, изображение не растягивается по двум осям независимо.

Канонические art-спрайты лежат здесь, в `art/gen/placeables/workshop/service_lift/`. Те же готовые runtime bytes подключаются в `outputs/rocket/dist/assets/placeables/workshop/service_lift/`, чтобы игра могла использовать их без дополнительной перекодировки.

## Alpha

Imagegen оставил слабый почти прозрачный haze в пустом фоне. При импорте:

- alpha `<=12` очищен до `0`;
- alpha `>=248` приведён к `255`;
- промежуточная alpha на реальном крае сохранена до runtime-normalization.

## Placement anchor

Статические спрайты всех эпох используют единый placement anchor:

```text
x = 95 LP
y = 224 LP
kind = bottom-center baseline
```

Это anchor размещения всего объекта, **не pivot движущихся частей**.

## Анимация

Цельный PNG используется как anchor/reference и как статический fallback.

Нельзя имитировать работу подъёмника покачиванием, вращением или масштабированием целого изображения. По `ref2game` физическая механика должна быть разрезана на реальные части.

Событийная схема:

`OFF → IDLE → NOTICE → WORK → FINISH → COOLDOWN → IDLE`

Главные события:

- `workshop_enter` — сервисный узел подходит/готовится к ракете;
- `loadout_changed` — реально снимает/ставит модуль;
- `launch_prepare` — инструмент отходит и паркуется.

### По эпохам

- **E0 1978:** каретка/таль едет по балке, крюк поднимается/опускается; длина цепи рисуется кодом.
- **E1 1986:** движется гидравлическая сервисная каретка и подвес; шланги дают вторичную реакцию.
- **E2 1998:** независимы мостовая каретка и сервисная головка.
- **E3 2015:** независимы модульная каретка, захват и service head.
- **E4 2035:** обязателен cut-out rig двух роботизированных рук: shoulder → elbow → wrist → gripper.
- **E5 2060:** ring статичен; отдельные manipulators работают через реальные joints. Cyan-индикация и glow принадлежат коду.

`manifest.json` намеренно не содержит выдуманных joint coordinates: они появятся только после отдельной генерации part-sheet и измерения утверждённых частей.
