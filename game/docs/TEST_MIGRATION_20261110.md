## Размеры E0: ограничение исходных данных

Требование точного равенства каждого `BUILDING_ANCHORS[key].e0.size` размеру PNG противоречит текущим исходникам `main`.
`e0.size` — размер показа на острове. Например, `gantry`: 56×32 при PNG 269×154; `factory`: 70×51 при PNG 283×207.
Точное равенство есть у `beacons`, `weather`, `radar`, для которых задано `smooth: false`; оно проверяется строго по заголовку PNG.
У остальных 11 построек проверяются положительные размеры, отсутствие увеличения относительно PNG, допустимые следы и якоря, наличие и целостность PNG.
Историческая таблица `E0_BUILDING_SIZES` не используется как описание фактического размера текущих файлов построек.
Исходники и ассеты ради выполнения неверного равенства не изменялись.

## Сборка и CI

В этой Windows-среде стандартный resolver esbuild получал отказ доступа при чтении родительских каталогов (`Cannot read directory "../../.."`).
Добавлен `game/tools/runtime-source-plugin.mjs`, общий для `build.mjs` и теста бандла: он явно читает относительные JS-модули внутри `game/src` и не ищет конфигурацию/пакеты в родительских каталогах.
Внешние импорты и выход за пределы исходников отклоняются. Новых зависимостей нет.

В `.github/workflows/game-ci.yml` после сборки добавлен `npm test`.
Матрица: Node 22 и 24, Ubuntu 24.04 и Windows. Имена артефактов различаются для каждой комбинации.
Шаг `Verify clean runtime tree` с запретом `art/`, `outputs/`, `work/` сохранён.
После тестов по-прежнему проверяются SHA-256 сборки и чистота всех отслеживаемых файлов.
Сборка пишет только игнорируемые `game/dist/vyshe-neba.html` и `.sha256`; тест бандла использует `write: false`.

В `npm test` используется `node --test "game/test/**/*.test.mjs"`.
Node самостоятельно раскрывает glob; двойные кавычки предотвращают раскрытие оболочкой. Это поведение описано в [официальной документации Node 22](https://nodejs.org/download/release/v22.23.3/docs/api/test.html#running-tests-from-the-command-line) и подходит для Windows и Linux.
Локально команда проверена на Windows с Node v24.19.0. Node 22 и Linux в этой среде недоступны; их фактический запуск обеспечит матрица CI после публикации изменений. Удалённый CI в этой работе не запускался.

## Как запускать

Из корня репозитория:

```sh
npm test
npm run build
npm run test:browser
npm run balance:quick
npm run balance
```

`balance:quick` вызывает `node game/tools/economy-bot.mjs`, `balance` — ту же команду с `--real`.
В PowerShell с запретом исполнения `npm.ps1` используйте `npm.cmd` с теми же аргументами.
Для юнит-тестов браузер и Playwright не требуются. Playwright в этой работе не устанавливался.

## Что не покрыто

Браузерная визуальная проверка, настоящий DOM, touch-ввод, Web Audio и снимки экрана без Playwright не проверены.
Сохранённый `render.browser.cjs` всё ещё использует старый стенд `game/src/render/dev/preview.html`, которого нет в `main`; наличие Playwright само по себе этот стенд не восстановит. Для полноценного запуска понадобится отдельная миграция браузерного стенда вне `game/src`.
Проверки интерфейса браузера и аудиостенда также не подтверждены в настоящем браузере. Production-происхождение арта, качество сжатия относительно оригиналов и исторические повреждения ассетов не являются частью юнит-набора.
