# Баланс, проход 1 (2026-11-10): решения и числа

Решения приняты ведущим по поручению владельца («сделай, чтобы было интересно играть и возвращаться; цели достижимые — „вот ещё немного“; подсказки; ракета сначала рулится туго; возврат из космоса своими руками»). Основание — `BALANCE_REVIEW_20261110.md`. Каждый пункт проверяется `npm run balance` (настоящая симуляция) и тестами.

## 1. Рулёжка: туго на старте, легче с прокачкой

Сейчас стартовая ракета поворачивает с множителем 0,5 и наклоняется до 11°, и владелец считает, что «рулится сразу хорошо».

| Параметр | Было | Стало |
| --- | --- | --- |
| `FINS_DEFAULT.turn` (sim/config.js) | 0,5 | **0,22** |
| `FINS_DEFAULT.maxTilt` | 0,20 рад (11°) | **0,12 рад (7°)** |
| `finsTurn(level)` (data/parts.js) | 0,45 → 1,1 (L8) → 1,6 (L12) → 2,2 (L18) | **0,22 → 0,55 (L3) → 1,0 (L6) → 1,5 (L9) → 2,0 (L12) → 2,4 (L18)**, кусочно-линейно |
| `finsTilt(level)` | 0,20 → 1,2 (L8), свободное вращение с L12 | **0,12 → 0,45 (L3) → 0,9 (L6) → свободное вращение (π) с L9** |
| `dragCut` | без изменений | без изменений |

Смысл: первые три уровня стабилизаторов (20/25/30 монет) ощущаются сразу — ракету становится возможно направить; свободное вращение (разворот носом вниз) открывается на L9, то есть в конце E2, ровно к вехе 100 км.

## 3. Возврат из космоса

Физика не меняется: выше `wellRadius` гравитации нет, атмосферы нет. Возврат = развернуть ракету носом к Земле (нужно свободное вращение, стабилизаторы L9), дать тягу, пока вертикальная скорость не станет отрицательной, затем при появлении притяжения развернуть носом вверх и оттормаживаться. Это должно быть выполнимо руками и автопилотом.

- `sim/flight.js`: в фазе `space` новые предупреждения `warn(s, 'space-turn', …)` (нос вверх, climb > 0, топливо есть, свободное вращение есть) и `warn(s, 'space-fins', …)` (то же, но `cfg.fins.maxTilt < TILT_FREE`). Подсказки на HUD (`i18n`): `hint.spaceTurn` = «Разверни носом к Земле и дай тягу», `hint.spaceFins` = «Для разворота нужны стабилизаторы ур. 9». Когда ракета падает и притяжение вернулось (`phase` снова `descent`, climb < 0): `warn(s, 'space-brake')` = «Носом вверх — тормози».
- `sim/autopilot.js`: режим `flip` уже есть; проверить, что миссия `space` с `canFlip` действительно разворачивает, гасит подъём и переходит в `descend` с посадочным планом; без `canFlip` миссия не стартует выше `SPACE_ALT − 200` (бот не должен терять ракеты). При необходимости поправить, чтобы ракета со всеми модулями L9 (база L3) по миссии `space` возвращалась и садилась в ≥ 80 % прогонов с skill 0,8 на seed 1–10. Это тест.
- `economy-bot.mjs`: перед вехой `landAlt ≥ 100 км` планировщик обязан довести `fins` до уровня свободного вращения (`finsTilt(level) ≥ TILT_FREE`), иначе не летит в космос; при `landAlt`-вехе цель полёта — `Math.min(need·1,03, SPACE_ALT·1,03)` с посадкой.

## 4. Каждому модулю — своя строка дохода (settle + итоги)

`data/economy.js` `PAYOUT`, `rules/settle.js` `report.coins`:

| Строка | Было | Стало | Чей модуль / постройка |
| --- | --- | --- | --- |
| путь (высота, расстояние) | как есть | как есть | двигатель, бак, блок, капсула |
| посадка | 12 × (1 + 0,2·эпоха) | **40 ×** | опоры |
| идеальная посадка | 20 × … × маяки | **60 ×** | опоры, маяки |
| кольца | 0 | **8 за кольцо, ×2 за центр, × (1 + 0,2·эпоха)**; `result.ringsCenter` если уже считается, иначе центр = кольцо с `offset ≤ 0,35` (sim уже знает `quality: 'center'`) | стабилизаторы |
| близкие пролёты | 0 | **5 за каждый, максимум 30, только при посадке** | обшивка, радар |
| экономия топлива | 0 | **+10 % от пути, если посадка с ≥ 20 % основного топлива** (`result.fuelLeft01`) | бак, капсула, авионика |
| шторм | как есть | как есть | метеостанция |
| цель вылета (§6) | 0 | **20 × (1 + 0,2·эпоха)** | все |

Все новые строки показываются на экране итогов отдельными строками с подписью, какой модуль их растит (`ui/screens/results.js`, `i18n`): «Кольца ×3 +24 (стабилизаторы)», «Посадка +40 (опоры)», «Экономия топлива +12 (бак)». Строки с нулём не показываются.

## 5. Цена аварии и добыча под залог посадки

`data/economy.js`: `CRASH_LOSS.partValueShare` 0,045 → **0,12**, `minimum` 12 → **20**, `purseShare` 0,5 остаётся. Новое `PAYOUT.crashLootShare = 0,5`: при аварии собранные монеты зачисляются наполовину (сейчас полностью). Спасательная станция по-прежнему возвращает часть (`rescueRefund`).

Подсказка на итогах после аварии (`report.hint` уже есть; дополнить полем `savedIfLanded`): «Посадка сохранила бы N монет» (N = `charged` + половина добычи), после мягкой посадки — строка «Посадка сохранила N монет» (`report.coins.saved`). Если причина `landing-speed` — chip «Опоры ур. N+1» и «Парашют»; `landing-tilt`/`landing-drift` — «Стабилизаторы ур. N+1»; `lost-in-space` — «Стабилизаторы ур. 9: разворот в космосе».

## 6. Цель на каждый вылет: «следующая высота»

`rules/next-steps.js` новая функция `flightGoal(profile)`: `goalAlt = max(record × 1,05, record + 200 м)`, но не выше `min(веха эпохи, SPACE_LINE_M)` если веха не взята, и округлённая вверх до 100 м; для первого вылета — 1 000 м. Показывается на пульте запуска («Цель: 3,4 км, бонус +20») и на HUD как отметка на полосе маршрута/рядом с высотомером (простая строка `hint.goal` «Цель 3,4 км» при подъёме, «Цель взята +20» один раз). В `settle.js`: бонус выплачивается при `landed && maxAlt ≥ goalAlt`; `result.goalAlt` передаётся из `makeFlightConfig` (`config.goalAlt`, число, метры).

## 7. «Что дальше» ведёт к тому, что чувствуется

`rules/next-steps.js` `collectPurchases`: доступные покупки сортируются не только по цене, а по классу эффекта: класс 0 — двигатель, бак, разгонный блок, капсула, стабилизаторы (до L3), опоры (если последняя авария была `landing-*`); класс 1 — постройки с эффектом в полёте (маяки, башня, охлаждение, топливо, радар, метео); класс 2 — остальное. Внутри класса — по цене. Экран хаба и итогов показывает первые 2–4.
