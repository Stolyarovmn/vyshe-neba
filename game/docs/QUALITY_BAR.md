# Планка качества «Выше неба»

Что значит «выглядит и ощущается как большая игра» применительно к этой игре, и как это проверять. Документ обязателен при приёмке любого экрана, спрайта, механики или балансного изменения. Пункт считается выполненным только по скриншоту или записи из игры, не по отдельной картинке и не по отчёту.

## 0. Четыре правила, из которых следует всё остальное

1. **Один взгляд.** Любой экран, табло или выноска читается за секунду: что это, что я могу сделать, что мне мешает.
2. **Каждая покупка видна в полёте.** Если уровень не меняет ничего из того, что игрок видит и чувствует в следующем вылете (высота, тяга, посадка, риск, доход), уровня быть не должно.
3. **Каждое действие отвечает.** Нажатие, покупка, старт, отделение ступени, касание, авария, смена эпохи — у каждого есть движение, звук и, где можно, вибрация в пределах 100 мс.
4. **Один мир, одна рука.** В кадре нет картинок из разных игр: одна плотность пикселя на сцену, одна палитра, одна камера, один свет (`game-production:art/docs/ART_DIRECTION_HD_PIXEL.md`).

## 1. Кадр (визуальная цельность)

Проверяется по скриншотам базы, ангара, лавки, пульта, полёта (старт, 1 км, 10 км, отделение, посадка), итогов — в портрете и ландшафте.

- [ ] Плотность пикселя едина внутри сцены: база 1 px арта = 1 px острова; полёт — своя одна плотность. Нет спрайта, который «резче» или «мыльнее» соседей.
- [ ] Палитра: 252 цвета острова плюс ≤ 8 акцентов эпохи; никакого глянца, градиентов, чистого чёрного контура, полупрозрачного края.
- [ ] Камера: на базе всё в изометрии 40°, в полёте всё сверху, иконки фронт 3/4. Объект под промежуточным углом — брак.
- [ ] Масштаб: здание занимает свою полянку; ракета на столе выше всех построек; самый мелкий читаемый объект ≥ 40 px по большей стороне на телефоне.
- [ ] Свет один: верх-слева, холодная тень справа-снизу; тени на землю рисует код одинаково для всех.
- [ ] Интерфейс по `UI_LANGUAGE.md`: пиксельный шрифт ≥ ×2, цифра 8 с двумя просветами, текст внутри рамок при 320×568 и 568×320, никаких карточек-таблиц-вкладок.
- [ ] Ничего не «приставлено»: ракета цельный цилиндр, купленная кабина видна сразу, сопло ступени скрыто до отделения, кольцо — тор с задней и передней половиной.

## 2. Ощущение (game feel)

Проверяется записью экрана 60 с: старт → подъём → отделение → посадка → итоги → покупка.

| Момент | Обязательно | Запрещено |
| --- | --- | --- |
| Отсчёт и старт | лампы готовности гаснут по одной, тряска нарастает с тягой, пар и пыль из-под стола, звук двигателя с «раскачкой», переход база → полёт ≤ 0,6 с | мгновенный прыжок в полёт без перехода |
| Подъём | камера мягко отстаёт, облака и трафик на своих высотах, табло высоты щёлкает барабаном, зоны высоты объявляются | пустое небо дольше 5 с, шум/«манка», падение кадров |
| Отделение ступени | хлопок, толчок камеры, ступень уходит вниз с вращением и остаётся видимой 1–2 с, сопло ядра загорается | ступень исчезает |
| Опасности | радар предупреждает заранее, близкий пролёт даёт всплывающий бонус, удар — искры, трещина обшивки, звук металла | удар без причины и без объяснения |
| Посадка | замедление времени у касания, пыль/брызги, пружина опор, штамп «ПОСАДКА», монеты летят в копилку | посадка, которую нельзя отличить от аварии |
| Авария | взрыв/разлёт частей, экран дрожит, одна строка причины и совет, что купить | сухой текст без показа, потеря всего прогресса |
| Итоги | счётчики тикают, строки дохода появляются по одной, «что дальше» показывает ближайшую покупку с ценой | таблица без движения |
| Покупка | здание появляется со строительными лесами и звуком, в полёте эффект отмечен подсказкой «новое» | тихая смена числа |
| Смена эпохи | церемония: лампы гаснут, пульт переоснащается, фанфара, здания меняют облик | только надпись |

## 3. Читаемость полёта (тест трёх секунд)

Покажи незнакомому человеку кадр полёта на 3 с. Он должен назвать: высоту, хватает ли топлива, растёт или падает скорость, есть ли опасность рядом. Если нет — HUD переделывается, а не подписывается.

- [ ] Высота — барабанный счётчик, цифры ≥ 5 px шрифта, без обрезки.
- [ ] Топливо и прочность — сегментные шкалы, красная зона с миганием.
- [ ] Вертикальная скорость — стрелка/лента с зелёным окном допуска посадки (ширина окна зависит от опор и маяков — это и есть видимый эффект покупки).
- [ ] Предупреждения — лампы и звук, не текст.
- [ ] Постоянная информация занимает < 10 % кадра; центр свободен.

## 4. Производительность и надёжность

- [ ] 60 fps на среднем телефоне 2022 года; кадр отрисовки ≤ 8 мс на высоте 20 км на холсте 1855×962 (регрессия волн моря исправлена в #146, держать замер).
- [ ] Автономный HTML ≤ 25 МБ, первый кадр ≤ 3 с на 4G.
- [ ] 0 ошибок консоли за полный цикл база → полёт → итоги → база; `__VN_TEST__.errors` пуст.
- [ ] Сохранение переживает перезагрузку на любом экране; миграции профиля покрыты тестами.
- [ ] `npm test` зелёный; `npm run balance` приложен к PR, если менялись `data/`, `rules/`, `sim/`.

## 5. Обучение и первые 10 минут

- [ ] Первый полёт от нажатия «ПУСК» до посадки ≤ 90 с, подсказки в сцене, не модальные.
- [ ] Первое улучшение куплено на 1–2 полёте, и его эффект виден в следующем вылете.
- [ ] К 10-й минуте игрок видел: кольцо, монеты, опасность, отделение ступени, аварию с объяснением, мягкую посадку.
- [ ] «Что дальше» никогда не пусто и никогда не предлагает покупку без видимого эффекта.

## 6. Балансные ворота (см. `BALANCE_REVIEW_20261110.md`)

- [ ] `npm run balance` (настоящая симуляция) укладывает каждую эпоху в ±30 % цели и кампанию в 10–14 ч.
- [ ] Ни в одной эпохе больше 40 % вылетов не повторяют один и тот же план (цель высоты ±5 %, тот же исход): иначе эпоха — гринд.
- [ ] У каждого модуля каждый уровень поднимает свою строку дохода или допуска не меньше чем на 8 %.
- [ ] Веха перехода эпохи требует полётного умения (высота и возврат), а не только монет.
- [ ] Авария стоит ощутимо (но не обнуляет): потеря 10–25 % стоимости модулей, с верхней границей.

## 7. Приёмка

1. **Пакет скриншотов** (делает исполнитель): 8 экранов × 2 раскладки × текущая эпоха, плюс запись 60 с полёта. Хранится в PR.
2. **Проверка по чек-листам** §1–§6: каждый пункт `да / нет / не применимо` с номером скриншота.
3. **Решение владельца** по скриншотам из игры. Замечания записываются списком «экран → объект → что ожидалось»; исправление идёт тем же PR.
4. **Готово** = владелец принял, CI зелёный, тесты и бот приложены, документы обновлены тем же PR (DESIGN/ART_DIRECTION/этот файл).

## 8. С кем сравниваем

Ориентиры по ощущению, не по стилю: *Learn to Fly 3* (отклик каждого апгрейда в следующем вылете), *Into Space 2* (ритм «вылет → покупка → вылет»), *Dome Keeper* и *Kingdom Two Crowns* (цельный пиксель и читаемость на телефоне), *Mini Metro* (ничего лишнего на экране), *Spaceflight Simulator* (честное отделение ступеней). Если наш кадр или момент слабее ориентира, пункт не принимается.
